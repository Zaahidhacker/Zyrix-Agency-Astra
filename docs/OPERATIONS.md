# Development and deployment

## Local development

Use Node.js 24 LTS (minimum 22.13) and npm.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Open `http://localhost:3000`. The public website and enquiry form work with local SQLite without external accounts. Data is created in `.data/astra.sqlite`, which is ignored by Git.

To enable `/admin`, run `npm run admin:hash` in a private terminal and put the generated `ADMIN_PASSWORD_HASH` and `SESSION_SECRET` values in `.env.local`. Restart the development server. The password prompt is visible in that terminal; do not run it in a recorded/shared session. Never put credentials in a `NEXT_PUBLIC_` variable, commit them or paste them into chat.

```sh
npm run lint
npm test
npm run build
npm run typecheck
```

Type checking after build includes Next.js’s generated route types. Tests use their own temporary SQLite database and synthetic data. The development launcher accepts native Next.js flags and translates the managed preview’s `--host` / `--strictPort` flags. It does not change the production runtime.

## Recommended production: Next.js + PostgreSQL

1. Import this GitHub repository into a Next.js-compatible Node hosting provider (for example Vercel), or deploy the Docker image to a container host.
2. Provision PostgreSQL. A Supabase PostgreSQL connection string can be used directly; this application does not require the Supabase client SDK. For serverless hosting use the provider’s supported connection pooler.
3. Set `SITE_URL` to the actual HTTPS origin, `DATABASE_URL`, the provider-appropriate `DATABASE_SSL`, `ADMIN_PASSWORD_HASH`, and a random `SESSION_SECRET` of at least 32 characters. Keep `ALLOW_SQLITE=false`.
4. Set `TRUSTED_IP_HEADER` only to a header the hosting proxy overwrites. On Vercel this can be `x-vercel-forwarded-for`. If unset, endpoints use a deliberately conservative shared limit; configure it before a public launch with meaningful traffic.
5. Build with `npm run build`. On conventional Node hosting start with `npm start`; in Docker the standalone server is the entry point. Use Node 24.
6. Visit `/admin`, verify a synthetic enquiry, edit and publish content, upload a test image, and check that records survive an application restart.
7. Set the real enquiry email in the CMS, replace concepts with approved projects as available, and publish only genuine testimonials/team details. Confirm the privacy text matches the agency’s actual retention policy.
8. Complete the browser acceptance matrix in `QA.md` and run a production Lighthouse/WebPageTest pass before launch.

`SITE_URL` must be correct **at build time and runtime** because some metadata routes are generated during the build. For a preview use its real origin and set indexing restrictions at your host. Never deploy the example domain as your canonical URL.

The database adapter creates its small schema idempotently on first access. Use a dedicated application database/schema and a least-privilege application role. The initial role needs permission to create the application tables. Back up the database before schema upgrades. PostgreSQL persistence and TLS must be verified against your actual provider; no external database credentials were available during this implementation.

## Container deployment

```sh
docker build --build-arg SITE_URL=https://your-domain.example -t astra .
docker run --env-file .env.production -p 3000:3000 astra
```

Terminate HTTPS at your hosting proxy. Supply environment values at runtime; the Docker ignore file excludes secrets and development databases.

For a single-instance self-hosted installation only, persistent SQLite is supported: set `ALLOW_SQLITE=true`, `SQLITE_PATH=/app/.data/astra.sqlite`, and mount a persistent volume at `/app/.data` writable by UID 1000. Do not use SQLite on serverless/ephemeral storage or across multiple independent application replicas. Back up SQLite using its backup facility or a consistent snapshot that includes WAL state; copying a live main database file alone is not sufficient.

## Environment reference

| Variable                  | Use                                                                         |
| ------------------------- | --------------------------------------------------------------------------- |
| `SITE_URL`                | Public canonical origin and form-origin allowlist; required in production   |
| `DATABASE_URL`            | PostgreSQL connection string; recommended in production                     |
| `DATABASE_SSL`            | Set `require` when the provider requires TLS                                |
| `ADMIN_PASSWORD_HASH`     | Salted scrypt hash generated by the helper; enables admin sign-in           |
| `SESSION_SECRET`          | Random secret ≥32 characters for signed 8-hour sessions                     |
| `TRUSTED_IP_HEADER`       | Optional trusted-proxy IP header; configure for per-client rate limiting    |
| `SQLITE_PATH`             | Local SQLite path; defaults to `.data/astra.sqlite`                         |
| `ALLOW_SQLITE`            | Explicit production SQLite opt-in; requires durable single-instance storage |
| `NEXT_TELEMETRY_DISABLED` | Set `1` to disable Next.js build/development telemetry                      |

## Enquiry workflow

Enquiries are validated, rate limited and stored before success is returned. A browser-generated UUID makes retries idempotent. The honeypot silently discards bot submissions. The owner reviews the newest 200 enquiries in `/admin`, marks them contacted or archived, and can permanently delete personal data after confirming the action. Archiving is not deletion.

The database is the source of truth; email delivery is not a dependency. No third-party message was sent and no notification provider was configured. An optional transactional notification/outbox integration is a future enhancement. Until enabled, the owner should check the workspace for leads.

## CMS

`data/content.json` seeds a fresh installation. Once the owner publishes, the versioned database document becomes authoritative. It manages projects and case studies, services, testimonials, team members, homepage SEO and public contact information. Optimistic version checks prevent one editor overwriting another editor’s published changes. Images are uploaded through an authenticated, size-limited endpoint, re-encoded as WebP, and stored with immutable public URLs. These URLs are for public portfolio media, not confidential uploads. Media currently lives in PostgreSQL/SQLite; move to object storage for a large asset library.

## Security and observability

Mutations require same-origin requests. Admin endpoints additionally require a signed, expiring, HttpOnly session with SameSite=Strict; HTTPS deployments set Secure. Password verification uses scrypt and timing-safe comparisons. Request bodies and uploads are bounded. SQL values are parameterized. Security headers restrict framing, external scripts and browser capabilities. Because Next.js uses inline bootstrap scripts, CSP permits inline scripts; a nonce-based CSP is an optional hardening extension.

Optional, opt-in Core Web Vitals collect LCP, CLS and INP without names, enquiry data or persistent visitor IDs. Do Not Track is respected. Metrics expire after 30 days and their averages are shown to the owner. These averages are not field percentile scores. No third-party analytics account is needed.
